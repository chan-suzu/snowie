# Производительность

Все цифры сняты на одной машине: экран 3440×1440, 180 Гц, масштаб 125%, NVIDIA GeForce RTX 4070 SUPER, 12 потоков CPU, Windows 11. Компьютер во время замеров не простаивал, поэтому для показателей уровня всего процесса приведена медиана нескольких прогонов.

## Как мерить

Встроенный бенчмарк делает воспроизводимый прогон: настройки по умолчанию (конфиг пользователя не читается), заранее насыпанные сугробы, фиксированный seed. Первые 5 секунд идёт прогрев, затем замер. Отчёт в Markdown пишется в файл:

```bash
snowie.exe --bench 20 --out report.md
```

Флаги: `--fps 30`, `--heavy` (метель), `--fireworks` (непрерывный салют), `--music`.

Профайлер на экране включается в трее («Профайлер») или в настройках. С переменной `SNOWIE_LOG=1` каждую секунду дописывается строка в `%TEMP%\snowie-profile.csv`.

Внешний замер, включая CPU процесса DWM (он компонует наш слой) и суммарную загрузку GPU:

```bash
powershell -ExecutionPolicy Bypass -File scripts\measure.ps1 -Seconds 20 -Env "SNOWIE_PRESNOW=1"
```

### Что значат метрики

| метрика | откуда берётся |
|---|---|
| CPU кадра по стадиям | `Instant` вокруг каждой стадии основного цикла: scan (окна, мониторы, ввод), update (симуляция), record (запись команд Direct2D), submit (`EndDraw`: передача драйверу), present |
| GPU кадра | D3D11 timestamp queries до и после отрисовки кадра, без блокировок, с опозданием на несколько кадров. Это время на шкале GPU между двумя метками: если GPU в это время выполнял работу других процессов, она тоже попадает в интервал. Поэтому стоимость самого Snowie честно отражает p50, а хвост показывает конкуренцию за GPU. Кроме того, видеокарта сбрасывает частоту при малой нагрузке, и время кадра в мс от этого растёт. |
| CPU процесса | `GetProcessTimes`, user и kernel отдельно. Совпадает с внешним замером: 5,78% против 5,94% |
| память | `GetProcessMemoryInfo`: working set, private bytes, пик |
| видеопамять | `IDXGIAdapter3::QueryVideoMemoryInfo`: использование этим процессом |
| хук мыши | события в секунду и CPU потока хука (`GetThreadTimes`) |

Сценарий: снегопад по умолчанию, сугробы на окнах и панели задач, 60 кадров/с.

| | v0.1 (до) | промежуточный вариант (сетки GPU) | сейчас |
|---|---:|---:|---:|
| CPU кадра, среднее / p95 | ~1,7 мс¹ | 1,16 / 2,77 мс | **0,53 / 1,02 мс** |
| запись команд (record), p50 / p95 | — | 0,14 / 2,21 мс | **0,13 / 0,67 мс** |
| GPU кадра, p50 | — | 4,6 мс | **0,7 мс** |
| CPU процесса, % одного ядра | 14,8¹ | 10,2 | **3,3** (медиана 3 прогонов, разброс 2,7–7,7) |

Разброс CPU процесса при одинаковой стоимости кадра почти целиком приходится на время ядра: present, ожидание swap chain и отправка команд драйвером видеокарты. Хук мыши здесь ни при чём: при обычном движении мыши (~30–40 событий/с) его поток тратит меньше 0,01% ядра.

## Что сделано

1. **Sprite batches.** Снежинки, комки снега и искры салюта рисуются одним вызовом `DrawSpriteBatch` на каждую текстуру, а не отдельным `DrawBitmap` на каждую частицу. Вся отрисовка частиц занимает около 0,1 мс.
2. **Сугробы в текстурах.** Каждый сугроб живёт в своей маленькой текстуре (ширина окна × высота сугроба), и каждый кадр он рисуется одним текстурным прямоугольником. Перерисовываются только изменившиеся сегменты по 256 px. Медленный рост от снежинок применяется не чаще раза в 300 мс, а изменения от зачерпывания снега, снегоуборщика и перекрытия окон — сразу.
   - Сначала были опробованы geometry realizations (готовые сетки на GPU). Профайлер показал, что сама их отрисовка стоит GPU 4–5 мс за кадр, а каждая пересборка — 2–3 мс CPU. От них отказались.
3. **Учёт изменений по сегментам.** Симуляция отмечает, какие сегменты сугроба изменились. Улёгшийся сугроб не перерисовывается совсем, а сглаживание его поверхности не отмечает сегменты, если изменения ниже 0,02 px.
4. **Частота монитора только по делу.** Частота монитора включается, пока снег в руке, летит снежок или движется окно, на котором есть снег, снеговик или след. Остальное время рисуется 60 кадров/с (настраивается: 30, 60, 144).
5. **Музыка.** Трек синтезируется только при первом включении и с частотой 22 кГц: 4,7 МБ вместо 6,8 МБ.
6. **Скрытие.** На паузе и в полноэкранных приложениях кадры не рисуются: поток спит.

## Что ещё можно ускорить

- **Убрать глобальный хук мыши.** Можно включать «кликабельность» оверлея только когда курсор над снегом (опрос курсора раз в кадр, переключение `WS_EX_TRANSPARENT`). Хук сейчас почти ничего не стоит, но с ним Windows будит наш поток на каждое движение мыши.
- **Dirty rects в `Present1`.** Позволят DWM перекомпоновывать только изменившиеся области. Сейчас DWM компонует весь полноэкранный слой каждый кадр.
- **30 кадров/с, когда снег просто падает.** Работа ядра и драйвера пропорциональна числу кадров.
